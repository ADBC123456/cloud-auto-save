# 网盘自动转存（自动搜索增强版）

网盘签到、自动转存、命名整理、发推送提醒和刷新媒体库一条龙；本版在 [cloud-auto-save-x v1.0.9](https://github.com/OzoO0/cloud-auto-save-x)（FastAPI + Vue3）基础上新增**定时自动搜索**与**链接自动维护**能力：任务只需填名字，分享链接由系统到点自动搜索、验证、填入；链接失效或过期未更新时自动全网换链。

> ⛔ 注意！资源不会每时每刻更新，**严禁设定过高的定时运行频率**，以免账号风控和给网盘服务器造成不必要的压力。

---

## 一、功能总览

### 基础能力（继承自上游）

- 🔄 **自动转存**：定时或按节目播出状态自动运行，转存分享链接中的文件
- 🔍 **资源搜索**：多源聚合搜索网盘资源，自动识别链接可用性、自动定位分享目录
- 📝 **智能命名**：内置/自定义正则规则，支持 TMDB 识别与重命名
- 📅 **追剧日历 / 影视发现**：豆瓣榜单浏览、播出时间追踪、转存进度展示
- 🔄 **数据同步**：基于 OpenList 的多网盘同步、网盘与 NAS 本地同步
- ✅ **自动签到**：夸克 / 天翼 / 百度每日签到领空间
- 🔌 **插件系统**：媒体库刷新、下载推送、strm 生成等
- 🔔 **通知推送**：Bark / Telegram / ntfy / 钉钉 / 飞书 / 企业微信 / 邮件等多渠道

### 本版新增

| 功能 | 说明 |
|---|---|
| UniSearch 搜索源 | 接入 unisearchso.shop（账号登录、token 自动续期），与网络公开/CloudSaver/PanSou 四源并行搜索 |
| 每任务独立自动搜索 | 每个任务单独设置 cron（默认每 2 小时），到点自动搜索分享链接 |
| 执行前预填 | 到执行时间链接仍缺失/失效时，先搜索补链再转存，不必等搜索定时到点 |
| 失效自动补链 | 四个时机自动重搜换链：手动执行失败后、全局调度每轮后、每 15 分钟链接体检、每任务搜索 cron |
| 时效换链 | 链接有效但超过时效（默认 48 小时）未更新 → 自动换到更新的分享，防止分享者弃更后任务停摆 |
| 候选择优 | 多个候选验证通过时按「更新时间最新 > 资源最大 > 集数最新」择优 |
| 真实验证 | 候选链接必须通过真实网盘验证（能读到分享内容）才采用；死链记入失效库永不复用 |
| 多级文件夹递归 | 分享内无论嵌套多少层文件夹，全部递归扫描，按保存规则匹配文件转存 |
| 坏链判失败 | 分享为空/链接残缺 → 判任务失败并封禁，立即进入修复链，不再静默卡死 |
| 新建任务默认开启 | 配置了任一搜索源时，新建任务自动打开"自动搜索"开关，只填任务名和保存路径即可 |
| 空链接建任务 | 开启自动搜索的任务，分享链接可留空，由自动搜索填入 |
| 媒体库分类 | 一次配置「网盘目录 ↔ OpenList 存储 ↔ Emby 媒体库」，自动从 Emby/OpenList 拉取并推算对应关系；建任务只选分类，OpenList/Emby 参数不用再手填 |

## 二、部署

### 2.1 前置条件

- Docker（Windows 用 Docker Desktop；服务器安装 docker-ce）
- 能拉取基础镜像（国内服务器先配镜像加速，见 2.5）

### 2.2 本地部署

```bash
cd cloud-auto-save
docker build -t casx:autosearch .
docker run -d --name casx \
  -p 5115:5115 \
  -v E:/docker/casx-data:/app/backend/data \
  --restart unless-stopped \
  casx:autosearch
```

- 访问：`http://127.0.0.1:5115`
- **数据持久化**：`-v` 挂载目录存放数据库（任务/账号/搜索源/通知配置全在其中），容器删除重建配置不丢；不挂载则重建即清零
- Windows 路径写 `E:/docker/casx-data`；Linux 任意路径如 `/etc/casx/data`

### 2.3 服务器部署

```bash
cd cloud-auto-save
docker build -t casx:autosearch .

# 若 5115 已有旧容器，先停掉
docker stop casx && docker rm casx

docker run -d --name casx \
  -p 5115:5115 \
  -v /etc/casx/data:/app/backend/data \
  --restart unless-stopped \
  casx:autosearch
```

云服务器在安全组放行 5115（建议仅放行自己的 IP，或前置 nginx + HTTPS）。若旧容器数据卷里已有数据库，`-v` 挂回原目录即可无缝继承。

### 2.4 docker-compose

```yaml
services:
  casx:
    image: casx:autosearch
    build: .
    container_name: casx
    ports:
      - "5115:5115"
    volumes:
      - ./data:/app/backend/data
    restart: unless-stopped
```

### 2.5 国内拉取镜像慢/失败

```bash
mkdir -p /etc/docker
cat > /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": [
    "https://docker.1ms.run",
    "https://docker.xuanyuan.me",
    "https://docker.m.daocloud.io"
  ]
}
EOF
systemctl daemon-reload && systemctl restart docker
```

或本地构建后离线导入：`docker save -o casx.tar casx:autosearch` → 传到服务器 → `docker load -i casx.tar`。

### 2.6 常用运维命令

```bash
docker logs -f casx                  # 实时日志（自动搜索/巡检记录在此）
docker restart casx                  # 重启
docker stop casx && docker rm casx   # 删除容器（数据在挂载目录不丢）
```

## 三、首次配置

### 3.1 创建管理员

首次打开 `http://IP:5115` → 初始化向导 → 创建管理员账号。若页面操作按钮缺失（只看到"刷新/执行全部"），退出重新登录一次即可恢复权限。

### 3.2 添加网盘账户

系统设置 → 网盘账户 → 添加：粘贴对应网盘的 Cookie 并启用。自动搜索只采用「已启用且验证有效」账户对应网盘类型的链接。

### 3.3 配置资源搜索源

系统设置 → 资源搜索，四张卡片：

| 源 | 需要配置 | 说明 |
|---|---|---|
| 网络公开（net） | 只需开关 | 默认开启，无需账号 |
| CloudSaver | 服务器/用户名/密码 | 自建 CloudSaver 服务时填 |
| PanSou | 服务器 | 如 https://so.252035.xyz |
| UniSearch | 服务器/用户名/密码 | 服务器填 `https://unisearchso.shop`，填账号密码保存，token 自动获取并续期 |

**至少启用一个源**，自动搜索才有产出；多源并行、结果自动去重合并。

### 3.4 配置通知渠道

系统设置 → 通知（卡片式配置，点卡片填参数，右上「总测试」发测试消息）。

**ntfy（零账号，手机装 App 即可）**

1. 手机安装 ntfy App（App Store / Google Play / GitHub Releases）
2. App 内点 **＋** 订阅一个**随机长主题名**（公共服务器上主题名即密码）
3. ntfy 卡片：`NTFY_URL=https://ntfy.sh`、`NTFY_TOPIC=主题名`、`NTFY_PRIORITY=3`（4 高 / 5 紧急响铃），其余留空
4. 保存 → 「总测试」→ 手机应立即收到

> 国内网络访问 ntfy.sh 不稳时可自建：`docker run -d -p 8090:80 binwiederhier/ntfy serve`，URL 改填自建地址。

**Telegram（用现有账号，不影响正常使用，无需挂机）**

1. 找 @BotFather → `/newbot` → 获得 token
2. 给 bot 发 `/start`（或拉进群）
3. 找 @userinfobot 查数字 ID（推群填群的负数 ID）
4. 配置 `TG_BOT_TOKEN` + `TG_USER_ID`

> 国内服务器直连 Telegram API 不通，需补 `TG_PROXY_HOST/PORT` 或 `TG_API_HOST` 反代地址。

**其它渠道速查**：Bark（iOS 装 App 复制地址）、钉钉/飞书/企业微信群机器人（建群加自定义机器人拿 webhook）、Server酱/PushPlus/iGot/WxPusher（需注册）、Gotify（需自建服务端）、SMTP（现有邮箱开授权码）。

### 3.5 媒体库分类（一次配置，建任务只选分类）

先在「插件管理」里填好 **openlist**（地址 + 管理员 Token，`storage_id` 可留空）和 **emby**（地址 + Token）两个插件，然后：

系统设置 → **媒体库分类** → 点「**一键识别**」→ 核对 → 「**保存全部**」。

系统会读取 Emby 的媒体库列表和 OpenList 的存储列表，按 Emby 媒体库路径自动推算它对应的网盘目录，例如：

| Emby 媒体库路径 | 读取方式 | OpenList 存储 | 推算出的网盘保存目录 |
|---|---|---|---|
| `/mnt/openlist/百度/TV/国产剧` | rclone 挂载 OpenList | `/百度`（网盘根目录 `/`） | `/TV/国产剧` |
| `/media/百度/TV/动漫` | strm 文件 | `/百度` | `/TV/动漫` |

两种方式路径结构一样（本地前缀 + OpenList 路径），所以都能识别。识别不出来的（如本地硬盘的库）会标出来，从下拉框选存储、点「选择」挑网盘目录即可。

每个分类还有「按 TMDB 自动选择」：电视剧 / 动漫 / 综艺 / 电影。建任务时关联了 TMDB 就会自动选中对应分类；同一类型有多个分类（如 国产剧 / 欧美剧）时，再按 TMDB 的出品国家匹配分类名里的「国产 / 欧美 / 日 / 韩」等字样。

> **rclone 挂载 vs strm**：rclone 让 Emby 直接读网盘里的视频，信息最全，但扫库、刮削都会访问网盘（库大时慢、易被限流），播放流量经过服务器，新文件要刷新 rclone 缓存才能看到。strm 只是存放播放链接的小文件，扫库快、几乎不碰网盘、播放直连网盘，但 Emby 拿不到完整的媒体信息和截图。

## 四、任务配置详解

### 4.1 创建任务（简化流程）

追剧任务页 → 右上「**新增任务**」→ 只需填：

- **任务名称**（同时是默认搜索关键词）
- **媒体库分类**（配置过 3.5 后会自动选好，保存路径随之自动填为「分类目录/剧名(年份)」）
- 「自动搜索」开关默认已打开（前提是配置了搜索源）

保存即可，分享链接留空由自动搜索填入。

插件选项里的 openlist / emby 参数不用填：任务执行时会按所选分类（老任务按保存路径匹配分类）自动补齐，只补空着的参数，手填的值优先。

### 4.2 自动搜索字段

| 字段 | 默认值 | 说明 |
|---|---|---|
| 开启自动搜索 | 新建时开 | 总开关 |
| 定时规则（cron） | `0 */2 * * *` | 此任务**搜索链接**的频率（五段式：分 时 日 月 周），与"运行星期"无关 |
| 搜索关键词 | 空 | 留空用任务名；资源命名与剧名差异大时可自定义 |
| 目标网盘 | 跟随任务账号 | auto=用任务绑定账户的网盘类型；也可手动指定 |
| 更新时效（小时） | 48 | 只接受该小时数内更新的分享链接，也是"时效换链"的判定线 |

### 4.3 链接自动维护机制（核心）

| 时机 | 行为 |
|---|---|
| 执行前预填 | 到执行时间链接缺失/失效 → 先搜索补链再转存 |
| 手动执行失败后 | 任务封禁 → 后台立即搜索补链 → 找到后自动重新转存 |
| 全局调度每轮后 | 批量修复所有失效/缺链任务 |
| 每 15 分钟链接体检 | 真实验证当前链接；坏链/空分享立即换链（残缺链接也能被发现） |

**时效换链**：链接有效但超过时效未更新 → 换到时效内更新的分享；找不到则保留原链接继续。
**候选择优**：验证通过的候选按「更新时间最新 > 单文件资源最大 > 集数最新」取第一。

### 4.4 转存执行：多级文件夹递归

任务执行时递归进入分享内**所有层级子文件夹**（最深 5 层）收集文件，按保存规则匹配转存；运行日志打印每个子目录的扫描条数。配置了「更新目录」正则时，匹配的文件夹仍走整目录同步（保留结构），其余递归。

### 4.5 通知触发规则

| 情况 | 是否通知 |
|---|---|
| 转存成功且有新文件 | ✅ 通知（含文件树） |
| 执行成功但无新文件 | 静默 |
| 任务执行失败 | ❌ 通知（含原因） |
| 自动搜索命中/换链 | 🔍 通知（含新链接与更新时间） |
| 系统自动修复成功 | 🔧 通知 |
| 搜索未命中 | 静默（等下轮） |

### 4.6 手动 API

```
POST /api/auto-search/run
Body: {"task_id": 123, "force": true}
```

指定任务立即搜索；省略 `task_id` 则搜索全部。

## 五、典型场景推荐配置

| 场景 | 运行星期 | 自动搜索 cron | 时效 |
|---|---|---|---|
| **日更内容** | 自动（TMDB）或全选 | `0 */2 * * *` | 48 小时 |
| **周更内容**（每周固定一天更新） | 只勾更新日和次日 | `0 10 * * 5,6`（按实际更新日） | 240 小时（10 天），常断更可到 336 小时 |
| **完结旧资源补全** | 手动勾 1 天/周 | `0 9 * * *` | 720 小时（30 天）或更大 |

> 关键经验：**时效必须大于内容更新周期**，否则资源安静一个周期就会被误判弃更而频繁换链。

## 六、常见问题

**Q：任务列表看不到"新增任务"按钮？**
退出重新登录（权限未加载）。

**Q：链接坏了既不报错也不换？**
确认任务"自动搜索"开关已打开；空分享/坏链会判失败并进入 15 分钟体检换链。

**Q：ntfy 测试收不到？**
手机 App 是否订阅同一主题名；换网络（国内访问 ntfy.sh 不稳）；`docker logs casx` 看发送是否报错。

**Q：频繁出现网盘 gzip 解码错误？**
账号被限流的征兆，调大全局调度与任务 cron 间隔。

**Q：怎么完全重置？**
停止容器，清空挂载的数据目录，重启容器即回到初始状态。

**Q：迁移到其它机器？**
拷贝挂载的数据目录到新机器同样位置，启动容器即可，全部配置任务账号都在里面。
